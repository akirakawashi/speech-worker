# Speech Worker

Самостоятельный проект фоновой обработки звонков. Разворачивается на
GPU-сервере без Kubernetes и вызывает существующий Whisper по HTTP.
GigaAM не подключён; зависимостей CUDA, PyTorch и локальных моделей нет.

Главное правило владельца 13.10.2026: воркер получает запись,
готовит аудио, распознаёт речь и доставляет результат бэкенду. LLM-вызовы,
анализ, оценку и сохранение итогов выполняет бэкенд в своей фоновой очереди.
[Владельцы операций](../speech-backend/docs/processing-ownership.md).
13.10.2026 LLM-код и его команды удалены из воркера. Оставшиеся политики
приёма/истории/хранения переносятся отдельными задачами.

Основной воркер последовательно выполняет задания `ingest` и `transcribe`:
получает записи NCC и Телфина, сохраняет оригиналы в отдельном MinIO,
готовит аудио через ffmpeg и доставляет результат Whisper бэкенду.
Приём по расписанию и очередь запускает одна команда `speech-worker`.
Бэкенд сохраняет расшифровку и ставит анализ. При сетевых сбоях готовый DTO
сохраняется в буфере PostgreSQL для доставки без повторного ASR.
[Доставка и восстановление](docs/transcription-delivery.md).

Код выделен 12.10.2026 из `speech-backend`. Проект устанавливается и запускается
самостоятельно. Схема PostgreSQL общая с бэкендом; миграциями владеет
`speech-backend`, требуемая ревизия — `sp_0016_evaluation_jobs`.
Исходные папки и Git-репозиторий владельца сохранены.

## Локальное окружение

Нужны UV 0.11.18+, Python 3.12, ffmpeg и ffprobe.

```bash
uv sync --locked
```

Для новой установки создать `.env` по шаблону; существующий файл сохранить.
Заполнить настройки своей базы речи, MinIO, Whisper и выбранного источника
NCC. Для автоматического приёма и доставки ASR нужен API бэкенда
со служебным токеном. Основному процессу адреса и ключи LLM не нужны.
Команда с ограничением `--stages` требует настройки только выбранных этапов.

Анализ, оценка, причины и сравнение моделей находятся в бэкенде:
[команды и выполненная очистка](../speech-backend/docs/llm-ownership.md).
Общий CPU-процесс — `speech-process`. В воркере отсутствуют LLM-клиенты,
скрипт продаж и параметры моделей анализа/оценки.

```bash
uv run --locked speech-worker
uv run --locked speech-worker --lanes daily --stages ingest,transcribe
uv run --locked speech-worker --lanes daily --once
```

Один процесс выполняет одно задание за раз. `--once` обрабатывает не больше
одного задания этапа без автоматического приёма; пустая очередь тоже завершается успешно.
`--queue-only` оставляет только обработку уже поставленных заданий,
`--sources ncc` ограничивает автоматический приём источником NCC.
При SIGTERM/SIGINT воркер заканчивает текущее задание и закрывает пул.

## Команды

| Команда | Назначение |
|---|---|
| `speech-worker` | Приём по расписанию и последовательная очередь получения/ASR |
| `speech-ingest` | Перечисление звонков и постановка заданий приёма |
| `speech-backfill` | Управление порциями истории NCC |
| `speech-sync-directories` | Справочники сотрудников и проектов NCC |
| `speech-prune` | Существующие правила хранения оригиналов и завершённых строк |

Все команды поддерживают `--help`. `speech-ingest` остаётся ручным инструментом.
Технические команды истории, справочников NCC и хранения сохранены до
переноса оставшихся правил. Оценку ставит и исполняет только бэкенд.

## Запуск на сервере

```bash
docker compose up -d --build
docker compose logs -f worker
```

Compose запускает один воркер на Linux-хосте. Используются сеть хоста для доступа
к существующему Whisper/model-proxy и отдельный том временного аудио.
MinIO остаётся на другой машине. Для `local_export` нужен дополнительный
read-only mount каталога записей; исходники и записи в образ не включаются.

После каждого этапа временное аудио удаляется. При следующем запуске
оставшиеся после аварии каталоги убираются с проверкой файловых блокировок;
активные задания других процессов сохраняются. Очистку внутренних файлов
контейнера Whisper проверяют отдельно. Удаление оригиналов из MinIO выполняет
только отдельная команда хранения по существующей политике.

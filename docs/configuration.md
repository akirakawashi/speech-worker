# Настройки воркера

Ниже описаны настройки текущего переходного кода. По главному правилу
13.10.2026 воркер получает, распознаёт и доставляет запись; LLM вызывает
бэкенд. Настройки/ключи LLM ещё используются старым путём и будут удалены
из воркера после переноса исполнения. Рабочие `.env` не изменяются.
[Цель перехода](../../speech-backend/docs/processing-ownership.md).

Поддерживаемые поля и значения по умолчанию определены в
`src/setting/config.py`. Pydantic Settings читает `.env` из рабочего каталога;
переменные окружения имеют приоритет. `get_settings()` кеширует настройки,
поэтому для применения новых значений процесс перезапускается.
В Docker файл окружения передаётся через `env_file`, порядок запуска —
в [развёртывании](deployment.md).

`.env.example` — короткий шаблон действующих параметров. Рабочие `.env`
при очистке сохраняются. Неизвестные ключи игнорируются
(`extra="ignore"`), включая старые `OPENROUTER_*` и `TRANSCRIPTION_*`.
Опечатка в имени тоже игнорируется; обязательные настройки выбранного
сценария проверяются при сборке его зависимостей.

## Что нужно для каждого этапа

| Этап | Настройки |
| --- | --- |
| Любая команда с очередью | `SPEECH_MS_DATABASE_URL`; параметры пула `DB_*` можно оставить по умолчанию |
| Сохранение и чтение аудио | `SPEECH_STORAGE_BASE_URL`, bucket, регион и ключи MinIO |
| Распознавание | `SPEECH_WHISPER_BASE_URL` и остальные `SPEECH_WHISPER_*` |
| Анализ и причины | `SPEECH_BACKEND_BASE_URL`, `SPEECH_WORKER_API_TOKEN`, `SPEECH_ANALYSIS_LLM_BASE_URL`; ключ LLM при необходимости |
| Оценка продаж | API бэкенда и служебный токен, `SPEECH_QUALITY_LLM_BASE_URL`, ключ и таймаут LLM |
| Приём NCC и Телфина | Настройки выбранного источника, перечисленные ниже |

MinIO находится отдельно от GPU-сервера. Локальные копии создаются в
`SPEECH_WORKER_TEMP_DIR`; это настройка каталога, а не срока хранения
оригинала. Очистка временных файлов и границы ответственности описаны в
[пути аудио](audio-flow.md#ответственность-за-очистку).

## Whisper и выполнение LLM

`SPEECH_WHISPER_BASE_URL` указывает корень OpenAI-совместимого API, обычно
с `/v1`. Воркер отправляет один подготовленный WAV в
`/audio/transcriptions`. Язык, модель, VAD и общий HTTP-бюджет задаются
`SPEECH_WHISPER_*`. Пустой адрес вызывает `WhisperNotConfigured`.
Дополнительных настроек выбора провайдера и fallback нет.

`infrastructure/transcription/execution.py` допускает одну HTTP-попытку:
частично отправленный multipart-запрос не повторяется автоматически.
Истечение бюджета преобразуется в `TranscriptionError("timeout")`;
внешняя отмена не маскируется. Повтор задания регулируется очередью.

`SPEECH_BACKEND_BASE_URL` — корень URL бэкенда, без `/internal/v1`.
Служебный токен должен совпадать с `SPEECH_WORKER_API_TOKEN` в бэкенде.
Бэкенд выбирает модель, лимит ответа и промпт, а воркер использует свой
адрес и ключ LLM для исполнения. Контракт описан в
[архитектуре](architecture.md#запросы-к-llm).

## Получение записей

Для `SPEECH_NCC_SOURCE_KIND=local_export` нужен `SPEECH_NCC_EXPORT_DIR`
с доступной процессу выгрузкой; в Docker требуется read-only mount.
Для `sequence` нужны адрес NCC, имя пользователя, токен и
`SPEECH_NCC_SESSION_ANCHOR`.
Для `reporting_view` нужны настройки REST-клиента, DSN представлений,
отдельный `SPEECH_NCC_REPORTING_DB_PASSWORD`, список представлений вида
`calls_detail=Волна,tss_7tel_calls_detail=7Телеком` и их часовой пояс.
Пароль reporting-базы используется отдельно от DSN и остаётся действующей
настройкой. Режим `rest` намеренно отклоняется: API кейсов не отдаёт
необходимый список сессий.

Телфин использует `SPEECH_TELPHIN_*` и `SPEECH_PHONE_HASH_PEPPER`.
Фильтры добавочных номеров и групп, глубина истории и минимальная длительность
остаются действующими параметрами.

## Удалённые настройки

`SPEECH_NCC_PROJECTS`, `SPEECH_NCC_SESSION_DOMAINS` и
`SPEECH_NCC_SESSION_NAUSS` не читались ни одним действующим источником.
OpenRouter и общие `TRANSCRIPTION_*` обслуживали старый путь загрузки
аудио и не использовались конвейером речи. Они удалены вместе с
невызываемыми помощниками; действующие команды и транспорт Whisper сохранены.
`RestCasesSource`, обход кейсов и поиск сессий в кейсах удалены: этот режим
уже отклонялся фабрикой и сохранялся только на будущее. REST-клиент записей
и справочников остаётся для `sequence` и `reporting_view`.
Общая граница очистки — [документация бэкенда](../../speech-backend/docs/configuration.md#очистка-12102026).

## Единый запуск

`speech-worker` запрашивает расписание у бэкенда. Интервалы, дневная доля NCC,
ночное окно и размер порции оценки задаются в окружении бэкенда. Воркер
хранит адрес, ключ и таймаут сервера оценки; `SPEECH_QUALITY_LLM_MODEL` и
`SPEECH_QUALITY_LLM_MAX_TOKENS` перенесены в бэкенд и в воркере не читаются.
[Контракт и значения по умолчанию](../../speech-backend/docs/worker-runtime.md).

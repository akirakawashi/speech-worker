# Контракт разделения 1.2

Документ фиксирует действующий переходный контракт очереди. Целевое правило
13.10.2026: воркер доставляет распознавание, бэкенд сохраняет его и сам
выполняет дальнейшие LLM-анализ/оценку. Приём и доставка ASR реализованы;
CPU-исполнитель бэкенда ещё предстоит подключить.
[Владельцы операций](../../speech-backend/docs/processing-ownership.md),
[порядок перехода](../../speech-backend/docs/refactoring-plan.md).

Дата выделения: 12.10.2026. Зафиксирован существующий формат взаимодействия
через PostgreSQL. Редакция 1.1 добавляет независимое задание оценки и служебный
HTTP API бэкенда. Редакция 1.2 от 13.10.2026 добавляет доставку ASR 1.0,
nonce и долговременный буфер. Воркер собственного HTTP-сервера не поднимает.

## Схема и владение

- База речи общая с speech-backend, адрес задаёт SPEECH_MS_DATABASE_URL.
- Миграциями и изменением схемы владеет speech-backend. Воркер не содержит
  своей копии Alembic и не запускает миграции.
- Требуемая ревизия: sp_0016_evaluation_jobs.
- Воркер сохраняет метаданные приёма и буфер доставки. Расшифровку и
  дальнейшие результаты записывает бэкенд; прежние LLM-команды переходные.
- Рабочие секреты каждого проекта настраиваются отдельно.

## Задания

DTO очереди: [NewJob и ClaimedJob](../src/application/ports/queue.py).
Основная цепочка: ingest → transcribe → analyze. Основной воркер берёт только
первые два вида задания, дальнейшие — исполнитель бэкенда. Отдельный вид —
evaluate, который бэкенд ставит только для готовых звонков Телфина.
Полосы: daily и backfill.
В payload передаются JSON-данные задания; бинарное аудио хранится в MinIO.

Сохраняются UUID звонка и задания, попытки, lease, run_after, priority и
метка not_before. Следующий этап наследует полосу и приоритет звонка.
Срочность сохраняется: свежие NCC — 0, отложенные NCC — 10,
Телфин — 20, история — 100.

Версия 1.1 обозначает договорённость в документации. Поле версии в существующий
payload не добавлялось, поэтому уже поставленные задания читаются без конвертации.
Nonce выдаётся при захвате даже заданию без новых метаданных; буфер имеет
явную версию DTO 1.0. Старую очередь нельзя запускать вместе с новой доставкой:
она не поддерживает её fencing, квитанцию и восстановление.
Изменение DTO или значений enum требует проверки совместимости обоих проектов
и обновления этой договорённости перед выпуском. Старые воркеры требуют
прежнюю ревизию схемы и должны быть остановлены до миграции.

## Результаты и повторы

Для ASR результат, завершение задания и постановка анализа фиксируются
в одной транзакции бэкенда. Воркер предварительно сохраняет только буфер.
Сеть, ffmpeg и вызовы моделей выполняются вне неё.
Просроченная аренда запрещает записывать устаревший результат.

Повторная запись расшифровки заменяет её целиком. Изменение реплик или ролей
снимает связанную оценку согласно существующим правилам. Текст хранится
без обезличивания; оценка продаж применяется только к Телфину.

Общий транспорт Whisper сохранён; конвейер использует SPEECH_WHISPER_*,
verbose_json и сегменты с таймкодами. Замена транспорта не должна менять
[DTO распознавания](../src/application/dto/transcription.py).

Доставка, срок хранения буфера, проверка квитанции и восстановление:
[доставка результата](transcription-delivery.md).

## Независимость проектов

Воркер не импортирует исходники соседнего проекта. Общие DTO и enum перенесены
как локальная версия текущего контракта. Новые изменения форматов согласуются
через контракт и тесты, а не через runtime-импорты из speech-backend.

Существующие исходники сохранены. До переключения запусков нельзя одновременно
включать старые и новые таймеры приёма/оценки для одной базы: это разные точки
запуска одних и тех же фоновых сценариев.

## Служебное управление

Основной воркер получает расписание приёма и доставляет ASR по Bearer-токену.
Готовые шаги оценки в сохранённых переходных командах выдаёт API бэкенда,
HTTP DTO имеют поле `contract_version=1.0`. Итог включает балл и счётчики,
рассчитанные бэкендом; воркер их повторно не вычисляет.
[Маршруты, запись и повторы](../../speech-backend/docs/worker-runtime.md).

# Запуск на GPU-сервере

Текущему воркеру нужны CPU, ffmpeg и доступ к существующим HTTP-сервисам.
Whisper продолжает работать в своём контейнере; настройки GPU и модели
воркер не меняет. GigaAM отсутствует.

## Доступ к бэкенду и LLM

Для этапа `analyze` задаём `SPEECH_BACKEND_BASE_URL`, общий с бэкендом
`SPEECH_WORKER_API_TOKEN` и `SPEECH_ANALYSIS_LLM_BASE_URL` с `/v1`.
Если сервер модели требует ключ, задаём `SPEECH_ANALYSIS_LLM_API_KEY`.
Промпт и model ID выбирает бэкенд. Сначала обновляем API, затем воркер;
старые переменные Dify не используются.
[Полный контракт и настройки](../../speech-backend/docs/model-execution.md).

## Развёртывание

Разместить проект в /opt/speech-worker либо скорректировать пути в шаблонах
systemd. Создать .env из .env.example, заполнить адрес общей базы речи,
MinIO, Whisper/model-proxy, API бэкенда, LLM и учётные данные используемых источников.
Скопированные рабочие секреты в репозиторий не входят.

К базе предварительно применяются миграции speech-backend до
sp_0015_drop_masking. Воркер проверяет схему при старте.

```bash
docker compose up -d --build
docker compose logs -f worker
```

Compose запускает один последовательный процесс с полосами daily,backfill.
Используется сеть Linux-хоста: адрес 127.0.0.1 в настройке Whisper указывает
на HTTP-порт этого сервера. Для MinIO указать адрес его отдельной машины.
Том worker-tmp принадлежит временным копиям воркера; UID/GID процесса — 10001.
Исходное аудио в образ не включается.

Если выбран local_export, добавить read-only mount каталога записей и
SPEECH_NCC_EXPORT_DIR внутри контейнера. Для reporting_view нужны настройки
отчётной базы NCC и HTTP-доступ к её записям.

## Приём и оценка по расписанию

Шаблоны находятся в [deploy/systemd](../deploy/systemd).
Включение таймеров на удалённом сервере пока не выполнялось.

| Таймер | Сценарий |
|---|---|
| speech-ingest-ncc.timer | Каждые 15 минут; дневная доля 0.5, остальные с 19:00; ночь до 07:00 по Москве |
| speech-ingest-telphin.timer | Раз в час с 19:00 до 06:00 включительно; priority 20 |
| speech-evaluate.timer | Раз в 15 минут, порция до 100 звонков; существующая отдельная оценка Телфина |

Каждый запуск использует тот же образ через docker compose run --rm.
Один service не запускается повторно, пока предыдущий прогон не завершён.
Для Телфина Persistent=false, чтобы пропущенное ночное задание таймера
не выполнялось днём после перезапуска хоста. Отложенные задания очереди
сохраняются и после ночи обрабатываются за свежими NCC.

Оценка оставлена круглосуточной, как в текущей реализации. Её перевод
на ночное расписание этими изменениями не выполняется.
Очистка постоянных оригиналов в MinIO автоматически не включается.

## Переключение

Сначала проверить новые команды и конфигурацию на стенде. При переключении
остановить старые воркеры и соответствующие таймеры для этой базы,
затем запустить новый воркер и нужные таймеры. API продолжает читать
те же таблицы, конвертация уже поставленных заданий не требуется.

Исходные проекты сохраняются. Шаблоны не устанавливаются автоматически
и действующие сервисы этими файлами не изменяются.

## Остановка и уборка

```bash
docker compose stop worker
```

SIGTERM позволяет завершить текущее задание; Compose даёт 35 минут.
После обычной ошибки временное аудио удаляется контекстом этапа. После
аварии следующий запуск удаляет собственные свободные каталоги с помощью
файловых блокировок; активные каталоги других процессов сохраняются.

Оригинал в MinIO остаётся. За временные копии внутри контейнера Whisper
отвечает сам Whisper: очистку в установленном образе проверяем на сервере.
Проверки разработки не подтверждают качество или скорость настоящей GPU-модели.

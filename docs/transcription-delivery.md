# Доставка распознавания в бэкенд

Реализована 13.10.2026. Основная команда `speech-worker` берёт только
`ingest` и `transcribe`. После Whisper она отправляет результат в
`POST /internal/v1/transcription-results`; расшифровку, завершение задания
и постановку анализа одной транзакцией записывает бэкенд.
Воркер не вызывает LLM после распознавания.

[Контракт HTTP 1.0 и пример запроса](../../speech-backend/docs/transcription-delivery.md),
[главное правило](../../speech-backend/docs/processing-ownership.md).

## Порядок выполнения

1. Очередь выдаёт `ClaimedJob` с владельцем и новым `_claim_token`.
   Счётчика попыток недостаточно: defer возвращает попытку, а имя процесса
   может совпасть с прежним. Heartbeat продлевает только этот живой захват.
2. Application читает сохранённый вход звонка. Если имеется буфер для того
   же объекта/числа каналов, использует готовый результат. Иначе скачивает
   аудио из MinIO, готовит WAV и выполняет прежнее распознавание и техническую
   атрибуцию. Качество ASR этим переносом не меняется.
3. Перед HTTP фиксирует полный неизменяемый DTO в
   `speech_jobs.payload._transcription_delivery` отдельной короткой транзакцией.
   SQL ещё раз проверяет nonce, владельца, попытку, живую аренду и вход.
   Сохранение буфера не завершает задание и не пишет таблицы расшифровок.
4. Отправляет DTO по служебному Bearer-токену. Повторы внутри захвата
   используют то же тело. Ответ должен иметь явную версию 1.0 и совпадающие
   call/job/nonce/attempt; статус 200 сам по себе недостаточен.
5. Бэкенд при commit удаляет буфер, оставляя квитанцию и хеш вместо копии
   текста. Воркер пропускает локальные `store`, `complete` и постановку анализа,
   затем останавливает heartbeat. Задания `analyze`/`evaluate` он не забирает.

## Повторы, отмена и перезапуск

HTTP-клиент выполняет максимум три попытки с паузами 1 и 2 секунды;
таймаут каждой задаёт `SPEECH_BACKEND_TIMEOUT_SECONDS`. Повторяемы сетевые
ошибки, таймауты, 408/409/429 и 5xx. Если доставка ещё не подтверждена,
сценарий возвращает `StageDeferred`: очередь откладывает задание на 60 секунд,
освобождает nonce и возвращает попытку, сохраняя готовый DTO. Недоступность
бэкенда не расходует бюджет вызовов Whisper.

Отмена после записи буфера оставляет его в базе. Сборщики просроченных
заданий обоих проектов сохраняют готовый результат и возвращают задание
в очередь даже на последней попытке. Авария до записи буфера использует
прежний ограниченный механизм повторов ASR.

При новом захвате создаётся новый nonce и DTO нового захвата с прежним
ASR-результатом, если вход совпадает. Это новая доставка; внутри одного
захвата подмена тела запрещена. При изменении аудио распознавание выполняется
заново. Повреждённый буфер или буфер другого звонка не отправляется.

Если бэкенд сделал commit, а ответ потерялся, повтор возвращает прежнюю
квитанцию. Само задание уже `done`, поэтому ни defer/fail, ни новый захват
не могут возобновить его из-за отсутствия HTTP-ответа. Операции текущего
воркера проверяют nonce, чтобы не затронуть новую аренду под тем же именем.

401/403/404/422, перенаправления и неверная квитанция — нормализованные
неповторяемые отказы. В сообщения и логи не передаются тело HTTP, текст
разговора, токен или SQL-параметры. Терминальный отказ снимает буфер;
подтверждённое другим запросом задание уже не принадлежит отправителю.

## Хранение и очистка

Буфер — одна временная копия текста на задание, а не новое хранилище аудио.
Его срок жизни: до commit бэкенда, терминального отказа, явной переобработки
или удаления задания/звонка. При недоступности бэкенда он сохраняется до
восстановления доставки; автоматического TTL для неподтверждённого текста нет.
Буфер переживает перезапуск контейнера и потерю его временного диска.

Временные MP3/WAV удаляются контекстом ASR после распознавания при успехе,
ошибке или отмене. Уже записанный DTO позволяет доставку без этих файлов.
Свободные каталоги после аварии убираются прежней проверкой файловых блокировок.
Оригинал остаётся в MinIO. Внутренними файлами контейнера Whisper владеет
сам Whisper: его очистка здесь не меняется.

## Состояние перехода

Нужен API с этим маршрутом и поддержкой буфера, а не только схема 16.
Миграции не добавляются. Рабочие `.env` не переписываются; используются
существующие адрес бэкенда, служебный токен и таймаут. Проекты не импортируют
исходники друг друга.

Основной реестр и CLI не принимают `analyze`/`evaluate`; старые LLM-модули и
отдельные команды ещё сохранены до переноса их потребителей. Анализ и оценка
реализованы командой `speech-process`:
[запуск и гарантии](../../speech-backend/docs/evaluation-processing.md).
Удаление дублей и переключение сервера — следующие задачи:
[план](../../speech-backend/docs/refactoring-plan.md).

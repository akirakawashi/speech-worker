# Разработка и проверки

Работаем в собственном окружении speech-worker. Python 3.12+; ffmpeg и ffprobe
нужны для настоящей подготовки аудио. Команды создания окружения находятся
в [README](../README.md#локальное-окружение).

## Зависимости и установка

requirements.lock фиксирует зависимости исполнения, requirements-dev.lock —
также Ruff, mypy и pytest. При выделении использованы версии из проверенного
окружения speech-backend. Docker устанавливает runtime lock и сам пакет.
Установка через uv всегда указывает --python .venv/bin/python.

При обновлении зависимостей заново собираем lock-файлы из pyproject.toml,
проверяем тесты и сборку образа. Список зависимостей не включает веб-сервер,
авторизацию API, PyTorch, CUDA или GigaAM.

## Статические проверки

Запускаем Ruff, ruff format --check и строгий mypy src в окружении проекта.
Тест архитектуры запрещает обход границ слоёв и импорты старого app.
Docstring новой функции объясняет действие, вход, выход, значимые ошибки
и побочные эффекты. Не подавляем ошибки ради успешного прогона.

## PostgreSQL под тестами

SPEECH_POSTGRES_TEST_URL направляем только в отдельную пустую тестовую базу.
Тесты очищают таблицы речи; speech, speech_test и рабочие базы не используем.
Имя должно содержать test, tests или ci как отдельную часть. Существующая
выделенная база — speech_whisper_test; для отдельного временного контейнера
можно создать speech_worker_test.

Перед прогоном применяем существующие миграции speech-backend к этой тестовой
базе до sp_0015_drop_masking. В самом воркере миграций нет.
SPEECH_REQUIRE_LIVE_PROOFS=1 делает пропуск проверок PostgreSQL неуспехом прогона.
SQL очереди, lease и блокировки проверяются на PostgreSQL, SQLite их не заменяет.

## Что проверяется

- Реальная PostgreSQL: claim, heartbeat, потеря lease, повторы, приоритеты,
  атомарная запись результата и постановка следующих заданий.
- Сценарии ingest, transcribe, analyze, источники NCC и Телфина, MinIO-транспорт,
  HTTP-клиенты и оценка по скрипту.
- Запуск выбранных этапов, неверные аргументы и закрытие пула при остановке.
- Очистка после успеха, ошибки, отмены и завершения процесса без finally;
  сохранение каталогов другого активного обработчика.

Проверки HTTP используют синтетические ответы и подставные транспорты;
они не измеряют качество или скорость настоящего Whisper/LLM.
После настройки сервера нужен отдельный прогон на его реальных HTTP-сервисах.

Для изменений только документации проверяем локальные ссылки и согласованность.

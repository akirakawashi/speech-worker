# Архитектура воркера

`speech-worker` — самостоятельный проект со своей сборкой и окружением.
Решение владельца 12.10.2026: разворачиваем на GPU-сервере без Kubernetes.
Текущая реализация использует существующий Whisper по HTTP.
GigaAM отложен: кода адаптера, настроек движка и зависимостей модели в проекте нет.

Главное правило владельца 13.10.2026: воркер получает и распознаёт запись,
передаёт результат бэкенду. Все дальнейшие LLM-вызовы, анализ, оценка и
сохранение итогов принадлежат бэкенду.
[Целевые границы и приём результата](../../speech-backend/docs/processing-ownership.md).

## Ответственность и ресурсы

Основной воркер получает команды бэкенда для готовых заданий, скачивает записи, сохраняет
оригиналы в MinIO, готовит аудио, вызывает Whisper и доставляет результат
бэкенду. Общая очередь и буфер неподтверждённого DTO находятся в PostgreSQL.
LLM-код и его отдельные команды удалены 13.10.2026; они принадлежат бэкенду.

GPU использует контейнер Whisper. Воркеру нужны CPU для ffmpeg, оперативная
память и временный диск. LLM остаётся отдельным HTTP-сервисом.
MinIO находится на другой машине; внутренняя сеть — 10 Гбит/с по словам владельца.
Бэкенд и фронтенд предназначены для CPU в Kubernetes.

## Слои

Таблица описывает текущие слои. Бизнес-модулей анализа/оценки в воркере нет.
14.10.2026 приём и история перенесены в бэкенд; перенос справочников и хранения
ещё остаётся. [Контракт ingest и владельцы](../../speech-backend/docs/intake-ownership.md).

| Пакет | Ответственность |
|---|---|
| `src/presentation` | CLI, разбор входных параметров, вывод результата |
| `src/application` | Сценарии, Pydantic DTO и порты внешних операций |
| `src/domain` | Модели и ограничения технического исполнения заданий |
| `src/infrastructure` | Технические операции очереди, источники, MinIO, ffmpeg, Whisper и доставка результата бэкенду |
| `src/setting` | Pydantic Settings только для фоновых процессов |
| `src/di` | Сборка выбранных ресурсов и управление их временем жизни |

Presentation вызывает application; application применяет domain и порты.
Infrastructure реализует порты, DI внедряет реализации. Domain не зависит
от других слоёв; application не импортирует infrastructure.
Точки входа CLI вызывают сборку DI после разбора аргументов.
Границы проверяет [тест архитектуры](../tests/test_architecture.py).

Параметры основного воркера проверяются через [WorkerOptions](../src/application/dto/worker.py).
Распознавание вызывается через порт `RecordingTranscriber` и возвращает
единый DTO текста, сегментов и таймкодов. HTTP-объекты, соединения БД и
файловые блокировки остаются в infrastructure.

## Целевой пайплайн

Доставка распознавания, CPU-анализ и оценка в бэкенде реализованы 13.10.2026.
LLM-потребители удалены; приём и история перенесены в бэкенд 14.10.2026.
[Фоновый анализ](../../speech-backend/docs/analysis-processing.md).
[Буфер, квитанция и повторы](transcription-delivery.md).

1. Бэкенд определяет допуск, расписание, приоритет и задание получения/распознавания.
   Его CPU-процесс сам запрашивает метаданные источников и регистрирует звонки.
2. Один воркер последовательно исполняет свои задания, удерживает lease и
   heartbeat. Приоритеты NCC, Телфина, истории и `not_before` сохраняются.
3. Воркер получает запись, измеряет её через ffprobe, сохраняет оригинал
   в MinIO; уже сохранённый оригинал повторно из источника не скачивается.
4. Воркер готовит WAV mono 16 кГц и отправляет один файл в Whisper по HTTP.
   Получает текст, сегменты, таймкоды и необходимые технические измерения.
5. Воркер доставляет DTO распознавания бэкенду. Бэкенд проверяет актуальность
   и аренду, сохраняет расшифровку, завершает задание распознавания и ставит
   дальнейшую обработку атомарно. Повтор доставки безопасен.
6. После commit бэкенд возвращает подтверждение, не ожидая LLM. Воркер
   очищает собственные копии; неподтверждённая доставка остаётся восстанавливаемой.
7. Фоновый обработчик бэкенда сам вызывает LLM, разбирает ответ и сохраняет
   анализ. Оценка — независимое задание бэкенда только для Телфина, NCC не оценивается.
8. Бэкенд выдаёт сохранённые результаты фронтенду. Оригинал остаётся в MinIO.

При ошибке сохраняется класс отказа, применяется существующая задержка
и ограничение попыток. Повторы не должны удваивать объект, транскрипт
или следующие задания. Обезличивание текста не возвращается.

## Время жизни и очистка

При запуске DI собирает зависимости только выбранных этапов и проверяет
ревизию схемы и необходимые таблицы. Пул PostgreSQL создаётся, используется
и закрывается в одном event loop, включая ошибку запуска и режим `--once`.
Сигнал остановки завершает текущее задание перед выходом.

Корень временного аудио задаёт `SPEECH_WORKER_TEMP_DIR`. Каждый каталог этапа
защищён файловой блокировкой Linux. После успеха, исключения или отмены он
удаляется. При запуске проверяются оставшиеся каталоги: занятые пропускаются,
свободные собственные каталоги удаляются. Создание каталогов и уборка
сериализованы отдельной блокировкой корня, чтобы не удалить создаваемое задание.

Исходная запись в MinIO остаётся до удаления отдельным сценарием хранения.
За файлы, принятые внутри контейнера Whisper, отвечает сам сервис модели;
фактическая очистка в работающем образе ещё не проверена.
Подробнее: [очистка](audio-flow.md#ответственность-за-очистку).

## Запросы к LLM

Воркфлоу Dify удалены. В воркере нет LLM-клиентов, промптов, скрипта продаж,
обработчиков анализа/оценки и записи их итогов. Runtime и CLI допускают
только `ingest`/`transcribe`; настройки LLM из шаблона и Settings удалены.
Рабочие `.env` сохраняются, старые ключи игнорируются.

Бэкенд выполняет модели локально через порты и общий `speech-process`.
Служебные маршруты выдачи готовых запросов и шагов оценки закрыты.
[Владение, команды и совместимость](../../speech-backend/docs/llm-ownership.md).

В воркере остаются скачиватели, подготовка аудио, Whisper и доставка ASR.
Получение и нормализация метаданных, допуск, дневная отсрочка, приоритеты
и история принадлежат бэкенду. Вторая копия этих сценариев удалена.
Остаются административные сценарии и хранение:
[план](../../speech-backend/docs/refactoring-plan.md).

## Контракты и состояние переноса

Очередь и таблицы результатов общие с `speech-backend`. Миграции принадлежат
бэкенду; требуемая ревизия — `sp_0017_analysis_storage`.
Форматы и границы владения описаны в [контракте разделения 1.4](contracts.md).
Проект собирается без исходников соседнего репозитория.

12.10.2026 фоновые команды и их зависимости выделены из копии в
`speech-backend`. Перенесены существующие тесты очереди, этапов, источников,
хранилища и оценки; добавлены проверки запуска, закрытия ресурсов и очистки
после аварии. Настройки API и политики хранения других приложений исключены.

Исходный `whisper-backend` сохранён. Старые обработчики получения/ASR и запуск
в новом бэкенде удалены 14.10.2026: [потребители и совместимость](../../speech-backend/docs/audio-worker-removal.md).
Dockerfile и Compose предназначены для независимого запуска на сервере;
удалённый сервер пока не переключён. Подключение GigaAM — отдельная будущая
работа, текущая реализация и настройки к нему не привязаны.
